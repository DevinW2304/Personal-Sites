Your Contributions

I owned this project end-to-end, from shaping the information architecture and designing the screens to structuring the JSON data and writing the front-end code. The goal was a calm, trustworthy grocery experience that still exposes rich product data.

Features I built:

  • Onboarding → login → sign-up flow using a consistent mobile shell.
  • Shop and category browsing with horizontal category chips and featured items.
  • Search view that queries the JSON catalog and renders responsive results.
  • Product detail pages with price, unit, tags, dietary info, and nutrition pulled from JSON.
  • Cart screen with editable quantities, line-item totals, and an order summary.
  • Payment preview and a lightweight profile area with mock order history.
  • A reusable DataAPI wrapper that loads and normalizes all JSON data.

Your Journey

Research & User Studies

Before locking in the flows, I ran short task-based studies with classmates and friends who shop for groceries online at least occasionally. Each session lasted about 15–20 minutes with think-aloud feedback.

Example tasks:

  • “Find a deli item you’d actually buy and add it to your cart.”
  • “Change the quantity of something in your cart without losing your place.”
  • “Check what pickup or delivery time slots are available tonight.”

Key insights:

  • People wanted a clear separation between browsing and search.
  • Users kept looking for a persistent cart summary with total and item count.
  • Product tiles needed more scannable info so people didn’t have to open every detail page.

Phased Development

  1. Phase 1 – Framing & IA: Defined the core journey (browse → product → cart → review) and mapped entities like products, categories, stores, inventory, users, and delivery slots.
  2. Phase 2 – Clickable Prototype & Testing: Built early HTML/CSS pages and iterated based on navigation confusion and content gaps.
  3. Phase 3 – DataAPI & Integration: Implemented the JSON-backed DataAPI and wired it into shop, category, search, product, and cart screens.
  4. Phase 4 – Polish & Microcopy: Tuned spacing, hierarchy, and labels so the experience felt calm instead of cluttered on a small screen.

What I Learned

  • Grocery UI becomes overwhelming quickly without strong hierarchy and clear copy.
  • Modeling the data early makes design changes less painful later.
  • Small usability tests can surface high-impact issues like cart affordance and label clarity.

Challenges & Skills Gained

  • Balancing realistic data and flows with a front-end-only scope.
  • Designing for thumb reach and one-handed use on a mobile viewport.
  • Writing small, reusable JS helpers instead of mixing logic into each page.

Key Flows

  • Onboarding & Access: Clear entry into login, sign-up, or continue as guest.
  • Browse & Search: Category chips and search UI hitting the same JSON product data.
  • Product Detail: Rich cards with price, unit, tags, dietary flags, and nutrition.
  • Cart & Payment Preview: Editable cart with totals plus a payment info view.
  • Profile: Lightweight profile and mock order history to suggest future personalization.

Visuals & Code

The final UI closely mirrors my Figma prototype. I kept the palette warm and neutral and leaned on spacing, typography, and small accents to make dense information (prices, sizes, tags) feel approachable on a phone screen.

Representative code snippet (DataAPI usage):

// Load all JSON once on app start
await DataAPI.loadEverything();

// Category view
const produceItems = DataAPI.getProductsByCategory('produce');

// Search view
const searchResults = DataAPI.searchProducts('coffee');

// Pricing helper
const firstResult = searchResults[0];
const effectivePrice = DataAPI.getEffectivePrice(firstResult);

This mirrors how a real API-driven app might work, but everything stays front-end only, which makes the project lightweight enough to host as part of my portfolio.

Implementation Details

Under the hood, the experience is backed by a set of JSON files that describe products, categories, inventory, stores, promotions, delivery windows, and mock users. The DataAPI wrapper handles loading and exposes helpers so each screen can focus on layout and interaction:

  • products.json – base catalog with categories, prices, tags, and nutrition.
  • categories.json – maps categories to IDs used throughout the UI.
  • stores.json – store IDs, names, and location data.
  • inventory.json – stock levels per store and product ID.
  • delivery_slots.json – pickup/delivery time windows.
  • promotions.json – discounts and featured banners.
  • users.json – mock users for login, profile, and order history.
